# Iroha v0.4.4 UI/UX quality plan

Status: reviewed and ready for implementation

Target release: `v0.4.4`

Task board: Asobi epic `iroha:0.4.4-ui-ux`

## Objective

Make the private cockpit easier to navigate, faster to understand, and more truthful in empty and default states without changing its API, data, or privacy contracts. Preserve Iroha's quiet, observant
identity and six registered design languages while using Grapher, the default language, to establish the reference hierarchy.

This patch is deliberately bounded. It fixes verified user-facing defects and extends the checks that guard them. Motion-system adoption, lazy theme loading, and a typed specimen platform remain
separate follow-up programs.

The plan combines:

- the live v0.4.3 cockpit, inspected on 2026-08-24 at desktop and 375px mobile widths;
- the current source, production build output, release history, and browser harness;

## Current situation

### What is already strong

- The product is specific: a private, evidence-preserving personal data cockpit rather than a generic health dashboard.
- All six registered languages are real compositions, not color swaps.
- The shared package owns theme identities, compositions, charts, and controls. Application routes remain data, URL, and async adapters.
- Sticky async resources prevent routine filter changes from replacing the whole data surface.
- Reduced motion is handled globally and explicitly in MapLibre and ECharts components.
- The mobile harness covers canonical and compatibility routes across six languages, light/dark, normal/reduced motion, and 320/375/390/414px widths.
- Sampled live routes emitted no browser errors, exposed accessible chart/map labels, and had no horizontal overflow at 375px.
- v0.4.3 has no open GitHub issues and `make web-build` passes.

## Decisions and constraints

1. **Grapher is the reference language, not a replacement language.** Shared fixes must keep all six languages passing.
2. **Use editorial and utility title scales.** Today and Overview may retain a large thesis; frequently used record pages use a compact scale.
3. **Keep ECharts drawing-only.** Svelte and semantic DOM own selection, URLs, focus, announcements, and evidence links.
4. **No D3 or Three.js dependency is expected in v0.4.4.** A future D3 leaf module requires a recorded seam justification and bundle comparison. No current user problem warrants Three.js.
5. **Keep the app/package boundary hard.** Routes own values, URLs, API state, and callbacks. Shared visual hierarchy and theme-aware presentation stay under `packages/iroha-shared`.
6. **Use `createAsyncResource` for route-owned request state.** Metrics' hand-written loading, error, and request-version state must not survive this patch.
7. **Do not infer observed metric dimensions from the catalog.** With no required dimension in the URL, show a truthful chooser before fetching/drawing. Write the URL only after the owner chooses.
   Explicit empty selections remain explicit.
8. **Treat 24x24px as an Iroha product floor for standalone controls.** Inline prose links retain the standard exception. Other WCAG 2.5.8 exceptions are evaluated explicitly rather than silently
   broadened.
9. **Verify changed behavior only against an isolated seeded release candidate.** The live v0.4.3 site is immutable baseline evidence, never proof of the patch.
10. **Never commit private evidence.** Screenshots, JSON audits, URLs, and fixtures committed to the repository must use seeded/canonical data. Live screenshots and DOM dumps stay temporary/gitignored
    and are deleted after non-sensitive findings are extracted.
11. **Each dispatched task changes at most five source, test, or documentation files.** If discovery requires more, split the task before editing. Generated seeded evidence does not count toward the
    implementation-file budget.

## Delivery plan

### Task 1: Make the verified accessibility failures executable

Extend the existing browser route audit with focused checks for a reachable skip link, one H1 before lower headings, compact-header focus order, and Iroha's 24x24px standalone-control floor. Do not
create a second browser stack.

Acceptance:

- focused fixtures reproduce the current four P0 failures before product changes;
- inline prose links are exempt; buttons, summaries, chips, and standalone record controls are not;
- the full existing language/mode/motion/viewport route matrix remains unchanged;
- audit output contains no live detail identifiers or private payloads.

Expected files (maximum 4): `scripts/mobile_route_check.py`, its focused test file, `docs/frontend-responsive-contract.md`, and one seeded audit fixture if needed.

Verify: focused script tests, `make scripts-test`, and a 375px seeded Grapher run.

### Task 2: Establish one canonical main landmark

Add a skip link and focusable `main` target without nesting landmarks or moving theme footers inside main content. Let `ThemeFrame` own the canonical landmark inside each package shell, normalize
Grapher's existing shell-level `<main>`, and account for the sticky header with focus visibility/scroll margin.

Acceptance:

- first Tab reveals the skip link; activation focuses unobscured main content;
- every themed private route exposes exactly one main landmark;
- theme footers remain outside the main landmark;
- language switching preserves a valid skip target without nested `<main>` elements.

Expected files (maximum 5): `apps/iroha-web/src/routes/+layout.svelte`, `apps/iroha-web/src/lib/themes/ThemeFrame.svelte`, the Grapher shell, `apps/iroha-web/src/routes/app.css`, and one focused test.

Verify: Task 1 landmark assertions, `make theme-boundary-check`, `make web-check`, and a seeded all-language landmark/skip-link pass.

### Task 3: Fix compact focus order and standalone target sizing

Make compact DOM and visual order agree. Raise host navigation controls and package-owned summaries, chips, and standalone record controls to Iroha's 24x24px floor through the narrowest shared
tokens/primitives that own them; do not style package internals from app CSS.

Acceptance:

- at 375px, focus follows the displayed top-to-bottom and left-to-right order;
- audited host and themed standalone controls meet 24x24px;
- focus indicators remain visible with at least 3:1 contrast;
- all six languages remain overflow-free at 320px and usable at 200% zoom.

Expected files (maximum 5): `NavigationMenu.svelte`, app shell CSS, package theme tokens or the shared owning control, one package composition only if it exposes the audited defect, and one focused
test.

Verify: Task 1 focus/target assertions, `make responsive-check`, `make theme-boundary-check`, `make web-check`, and seeded 320/375px normal/reduced-motion checks.

### Task 4: Correct Today and Overview heading semantics

Keep support modules useful without letting them outrank the page thesis. Replace pre-H1 support headings with labelled-region semantics or place them after the page heading where the composition
allows.

Acceptance:

- H1 is the first exposed heading on Today and Overview in every language;
- To-go and archive totals remain named regions with accessible controls;
- no sticky-resource or loading behavior changes;
- seeded screenshots retain each language's existing composition.

Expected files (maximum 4): the Today route, Overview route or composition adapter, `ArchiveTotals.svelte`, and focused tests.

Verify: heading audit, `make web-test`, and seeded Today/Overview visual checks in all six languages.

### Task 5: Give empty Today a useful next action

When the selected current day has no records and canonical bounds provide an earlier maximum, offer `Jump to latest recorded day`. Preserve the honest selected date and URL-owned navigation.

Acceptance:

- the action appears only when a distinct latest canonical day exists;
- activation navigates through the existing date/URL contract;
- loading, error, empty-with-latest, and empty-without-latest states are distinct;
- refetches preserve the sticky data surface.

Expected files (maximum 4): the Today route, `today-state.svelte.ts`, and focused route/state tests.

Verify: focused Vitest cases, `make web-test`, and seeded empty-day browser checks.

### Task 6: Establish compact Grapher utility hierarchy

Add a package-owned semantic utility title scale and apply it to Motion, Night, Patterns, and Library. Preserve each route's question and archetype; change hierarchy and spacing, not typography family
or personality.

Acceptance:

- each route's primary answer or filter is visible without scrolling at 1440x900;
- at 375px the title no longer consumes most of the viewport;
- Today and Overview remain editorial;
- no page-local raw title size duplicates the semantic token.

Expected files (maximum 5): `packages/iroha-shared/src/theme/themes.css` and the four Grapher route compositions.

Verify: seeded 1440x900 and 375x844 screenshots, `make theme-boundary-check`, and `make web-check`.

### Task 7: Make Metrics selection and async states truthful

Stop auto-selecting an unobserved required dimension. When a required dimension is absent, render a labelled chooser and defer the series request; after selection, write the URL and load through
`createAsyncResource`. Preserve explicit empty dimensions and name the selected metric, period, and dimension in the empty state.

Acceptance:

- `/metrics` presents a currency chooser rather than an empty EUR plot;
- choosing JPY updates the URL and loads its series;
- explicit `dimension=currency:EUR` remains EUR and explains that no observations exist;
- loading, error, all-null, and partial states are distinct;
- rapid filter changes cannot let a stale response replace the latest selection.

Expected files (maximum 4): `apps/iroha-web/src/routes/metrics/+page.svelte`, one co-located state helper, focused tests, and a shared empty-state file only if its existing contract cannot express the
copy.

Verify: Vitest cases for chooser, URL synchronization, explicit empty, all-null, partial, and stale response; `make web-test`; seeded JPY/EUR browser checks.

### Task 8: Restore keyboard-equivalent Patterns evidence navigation

Keep ECharts as the visual renderer. Make the persistent data-table/evidence path semantic: drillable periods, including null-valued periods where an evidence route exists, use real links or buttons.
Add a persistent selected-period summary only if it fits within this task's five-file budget; otherwise record it as follow-up.

Acceptance:

- pointer and keyboard users can open the same period evidence;
- Tab reaches semantic controls, Enter/Space follows native element behavior, and visible focus is preserved;
- labels name the period and value/absence without relying on canvas tooltip state;
- reduced motion reaches the same state without animated travel.

Dispatch as two parity increments after verifying the pattern exists in all six registered Daily compositions:

- 8a (maximum 5 files): add the mouse-only-row audit/test and replace row clicks with native period controls in Atlas, Grapher, and Field Journal;
- 8b (maximum 4 files): apply the same semantic control to Phenology, Sound Map, Archive, and the app fallback.

Verify: component tests, manual seeded keyboard pass at desktop and 375px, `make web-test`, and `make theme-boundary-check`.

### Task 9: Record a calibrated UI/UX scorecard

Use seeded fixtures to score a representative archetype set rather than every route: Today, Overview, Patterns, Metrics chooser/empty, To-go, and Admin across all six languages where registered.
Record Philosophy, Hierarchy, Execution, Specificity, Restraint, and Variety with evidence and reviewer identity. Subjective scores inform linked follow-up issues; they are not executable release
gates.

Acceptance:

- every evidence path resolves to a seeded/canonical fixture;
- the audit records route, language, mode, viewport, motion preference, build commit, and reviewer;
- disagreements or sub-3 findings become explicit follow-up items, not silently waived exceptions;
- no private identifier, payload, screenshot, or live URL is committed.

Expected files (maximum 2): one dated audit and, only if required, one canonical fixture manifest.

Verify: audit link/path check and a privacy review of every committed artifact.

### Task 10: Release the bounded v0.4.4 patch

Run the complete structural matrix against the isolated seeded release candidate, update timeless docs affected by the implementation, bump `VERSION` to `0.4.4`, add the changelog entry, and prepare
the PR. Do not deploy or publish a GitHub release.

Acceptance:

- 320/375/390/414px, light/dark, normal/reduced-motion structural checks pass for all registered languages;
- manual keyboard, 200% zoom/reflow, and screen-reader smoke checks cover Today, Patterns, Metrics, and To-go; the screen-reader record names the tested browser/reader, flow, and expected
  announcements;
- release evidence records exact seed, `BASE`, routes, themes, viewports, cache state, and build commit;
- `VERSION`, changelog, UI docs, and rendered version agree on `0.4.4`;
- a fresh-context review finds no blocking standards/spec issue.

Expected files (maximum 5): `VERSION`, `CHANGELOG.md`, the final audit, and at most two implementation-affected timeless docs.

Verify: `make check`, `make validate`, `make release-candidate`, the complete seeded `make web-mobile-check`, targeted seeded `make web-visual-check`, and fresh-context review.

## Follow-up epics (not v0.4.4 scope)

The source knowledge remains useful, but these programs should not hide inside a patch:

1. **Semantic motion:** inventory `state change | owner | channels | timing | reduced-motion result | route`, classify public/private parity, then define only repeated semantic tokens and adopt one
   bounded vertical slice. Frequent keyboard actions remain instant.
2. **Lazy theme delivery:** first separate synchronous exhaustive metadata from typed route loaders; then integrate private loading/error/latest-selection-wins/focus behavior; finally integrate the
   public static workshop. Measure five-run cold-cache median JS+CSS transfer, LCP, CLS, and first themed composition visibility on the same host.
3. **Typed specimen catalog:** adopt ThreeUI's route/language/fixture/contrast/motion/data-state/source/acceptance metadata pattern through real shared compositions and canonical fixtures, without
   copying its React/WebGL implementation or introducing private data.
4. **Broader hierarchy:** extend the package-owned utility header contract to registered Expenses/Reports and app-only Admin/Manual in separate tasks.
5. **Richer chart inspection:** define period-level Arrow Left/Right, Home/End, persistent summary, `aria-live`, and evidence activation semantics before changing a drawing renderer.

## Risks and mitigations

| Risk                                                | Impact | Mitigation                                                                                |
| --------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------- |
| Six languages multiply every visual change.         | High   | Change shared semantics first, then run explicit all-language checkpoints.                |
| Hierarchy cleanup erases personality.               | High   | Change scale and information order, not font family, color, or signature composition.     |
| Metrics invents observations it cannot know.        | High   | Require an explicit chooser; never infer coverage from catalog membership.                |
| Visual evidence leaks private cockpit data.         | High   | Commit only seeded fixtures; keep live captures temporary and delete them after analysis. |
| Automated checks create false confidence.           | High   | Retain named manual keyboard, zoom, screen-reader, and representative hierarchy reviews.  |
| D3/Three.js or architecture work expands the patch. | Medium | Keep both out of v0.4.4 and dispatch follow-up epics independently.                       |

## Definition of done

v0.4.4 is complete only when:

- the four verified P0 accessibility failures are fixed and guarded;
- utility-page first-view hierarchy improves without flattening the six design languages;
- Today and Metrics empty/default states lead to useful, truthful outcomes;
- Patterns evidence navigation is equivalent for pointer and keyboard users;
- all committed evidence is seeded and privacy-reviewed;
- `make check`, `make validate`, `make release-candidate`, the full seeded browser matrix, and fresh-context review pass;
- `VERSION` and changelog identify v0.4.4;
- the feature branch is pushed and a GitHub PR is opened, with no deployment or release publication.

## Rollback

Keep tasks in small conventional commits. Accessibility and truthful-state fixes remain independently revertible from hierarchy work. There is no database, API, importer, or public/private boundary
change, so rollback is source-only.
