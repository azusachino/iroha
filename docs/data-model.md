# Data Model

## Database

Use PostgreSQL with PostGIS from day one.

The route and privacy features are geospatial at the core. Starting with PostGIS avoids a migration away from a simpler store once route queries, heatmaps, and privacy zones matter.

## ORM and Migrations

Use an ORM for application data access, but keep database migrations explicit.

Preferred ORM:

```text
GORM
```

Reason:

- It is a pragmatic fit for a single Go server.
- It keeps CRUD code simple.
- It does not force the whole schema into a code generator.
- It still allows raw SQL for PostGIS-heavy queries.

Do not rely on ORM auto-migration as the source of truth. Postgres extensions, geospatial indexes, constraints, and data migrations should stay in reviewed migration files.

Use the ORM for:

- mapping rows to Go structs
- ordinary inserts, updates, and queries
- transaction boundaries
- simple associations such as `tb_raw_files -> tb_import_jobs`

Use explicit SQL for:

- `create extension`
- PostGIS columns and indexes
- complex route/geospatial queries
- migration steps
- bulk route-point replacement during reprocessing

## Migration Files

Migration files describe how the database schema changes over time.

`up` means apply the change:

```text
create table
add column
create index
enable extension
```

`down` means revert that same change:

```text
drop index
drop column
drop table
```

The names are conventional. User-facing scripts can call these `apply` and `rollback` if that reads better.

Preferred tool:

```text
Goose
```

Expected layout:

```text
apps/
  iroha-server/
    db/
      migrations/
        00001_enable_extensions.sql
        00002_create_import_core.sql
        00003_create_activity_core.sql
```

Nix should provide the migration CLI. Repo scripts can wrap it for convenience, but the migrations themselves remain ordinary SQL files.

Expected commands:

```bash
iroha-db migrate apply
iroha-db migrate rollback
iroha-db migrate status
```

Those commands can be implemented later as `uv` scripts that call the Nix-provided migration tool. Internally, Goose still uses the terms `up` and `down` inside migration files.

First migration:

```sql
create extension if not exists postgis;
```

UUIDs should be UUIDv7, generated by the application so IDs are time-sortable. Keep `created_at`, `started_at`, and other domain timestamps as explicit indexed columns; UUIDv7 ordering is useful for locality and cursor pagination, not a replacement for timestamp queries.

API IDs should be prefixed strings:

```text
raw_<uuidv7>
imp_<uuidv7>
act_<uuidv7>
```

Database columns should remain native `uuid` values. Prefix encoding and decoding belongs at the API boundary.

## Core Rule

Do not model one uploaded file as one activity.

Apple Health and Strava export zips can contain many activities. A raw file is source evidence; an activity is a normalized domain object discovered inside that evidence.

## Tables

### tb_raw_files

Stores immutable uploaded bytes.

```sql
create table tb_raw_files (
  id uuid primary key,
  sha256 text not null unique,
  original_filename text not null,
  content_type text,
  size_bytes bigint not null,
  storage_path text not null,
  source_kind text not null,
  uploaded_via text not null,
  created_at timestamptz not null
);
```

### tb_import_jobs

Stores parser attempts against raw files.

```sql
create table tb_import_jobs (
  id uuid primary key,
  raw_file_id uuid not null references tb_raw_files(id),
  status text not null,
  parser_kind text not null,
  parser_version text not null,
  error_message text,
  started_at timestamptz,
  finished_at timestamptz,
  created_at timestamptz not null
);

create index idx_tb_import_jobs_status on tb_import_jobs(status);
```

### tb_activities

Canonical workout/activity record.

```sql
create table tb_activities (
  id uuid primary key,
  sport_type text not null,
  title text,
  started_at timestamptz not null,
  ended_at timestamptz,
  timezone text,
  distance_m numeric,
  duration_s integer,
  moving_time_s integer,
  elevation_gain_m numeric,
  avg_hr integer,
  max_hr integer,
  avg_pace_s_per_km numeric,
  source_kind text not null,
  source_activity_id text,
  first_raw_file_id uuid references tb_raw_files(id),
  created_at timestamptz not null,
  updated_at timestamptz not null
);

create index idx_tb_activities_started_at on tb_activities(started_at desc);
create index idx_tb_activities_sport_started on tb_activities(sport_type, started_at desc);
```

### tb_external_refs

Links canonical activities to provider identities.

```sql
create table tb_external_refs (
  id uuid primary key,
  activity_id uuid not null references tb_activities(id) on delete cascade,
  provider text not null,
  external_id text not null,
  raw_file_id uuid references tb_raw_files(id),
  created_at timestamptz not null,
  unique(provider, external_id)
);
```

### tb_activity_route_points

Route geometry and per-point metrics.

```sql
create table tb_activity_route_points (
  activity_id uuid not null references tb_activities(id) on delete cascade,
  seq integer not null,
  ts timestamptz,
  lat double precision not null,
  lon double precision not null,
  elevation_m numeric,
  distance_m numeric,
  speed_mps numeric,
  heart_rate integer,
  geom geography(Point, 4326) not null,
  primary key (activity_id, seq)
);

create index idx_tb_route_points_geom on tb_activity_route_points using gist(geom);
```

### tb_activity_samplings

Time-series metric readings that are not necessarily route points.

Examples:

- heart rate
- cadence
- power
- body temperature
- oxygen saturation

The name `sampling` follows HealthKit/FIT-style language: one timestamped measurement from a stream.

```sql
create table tb_activity_samplings (
  id uuid primary key,
  activity_id uuid not null references tb_activities(id) on delete cascade,
  sampling_type text not null,
  ts timestamptz not null,
  value numeric not null,
  unit text not null
);

create index idx_tb_samplings_activity_type_ts on tb_activity_samplings(activity_id, sampling_type, ts);
```

### tb_activity_laps

Lap or split records.

```sql
create table tb_activity_laps (
  id uuid primary key,
  activity_id uuid not null references tb_activities(id) on delete cascade,
  lap_no integer not null,
  start_ts timestamptz,
  end_ts timestamptz,
  distance_m numeric,
  duration_s integer,
  avg_hr integer,
  avg_pace_s_per_km numeric,
  unique(activity_id, lap_no)
);
```

## Deferred Tables

These are part of the product model but not required for the first import path.

### gear

```sql
create table gear (
  id uuid primary key,
  kind text not null,
  name text not null,
  started_at date,
  retired_at date,
  distance_limit_m numeric,
  created_at timestamptz not null
);
```

### tb_activity_gear

```sql
create table tb_activity_gear (
  activity_id uuid not null references tb_activities(id) on delete cascade,
  gear_id uuid not null references gear(id),
  primary key (activity_id, gear_id)
);
```

### tb_activity_notes

```sql
create table tb_activity_notes (
  activity_id uuid primary key references tb_activities(id) on delete cascade,
  markdown text,
  mood text,
  weather text,
  tags text[] not null default '{}',
  updated_at timestamptz not null
);
```

### tb_privacy_zones

```sql
create table tb_privacy_zones (
  id uuid primary key,
  name text not null,
  center geography(Point, 4326) not null,
  radius_m integer not null,
  enabled boolean not null default true
);
```

### tb_published_activities

```sql
create table tb_published_activities (
  id uuid primary key,
  activity_id uuid not null references tb_activities(id),
  slug text not null unique,
  visibility text not null,
  sanitized_payload jsonb not null,
  published_at timestamptz not null,
  revoked_at timestamptz
);
```

## MVP Table Cut

Create these first:

- `tb_raw_files`
- `tb_import_jobs`
- `tb_activities`
- `tb_external_refs`
- `tb_activity_route_points`
- `tb_activity_samplings`
- `tb_activity_laps`

Add notes, gear, privacy zones, and publishing after the import and activity detail path works.
