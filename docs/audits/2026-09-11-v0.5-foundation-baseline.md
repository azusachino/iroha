  the cut-over.
- `make validate` is not a valid proof against the shared legacy development database: its `db-up` path correctly stops at the fresh-cut-over guard when old source observations lack receipt context.
  The isolated `make release-candidate` path is the release proof for v0.5; no legacy database migration was added to make `validate` appear green.
- A failed migration guard was exercised on disposable `iroha_task2_fail_20260911`: migration 00014 rejected an orphan source observation with
  `source observations without receipt context cannot be cut over; replay raw evidence first`. The completed release path applies the same migration chain to a clean database and replays evidence
  instead.

These are boundaries to carry into the owner handoff, not hidden successes. The legacy database remains available only for comparison/rollback until the cut-over is explicitly accepted.
