# Iroha v0.4.1 release audit

Date: 2026-08-15

Source branch: `feat/iroha-0.4.1-cache`

Release boundary: local source tag `v0.4.1`

## Scope

This is the final release evidence for the v0.4.1 cache, canonical read-projection, media-history, and media-detail corrections. The canonical-data-first rule remains unchanged: Postgres is
authoritative, the runtime cache is disposable, and provider snapshots are not exact consumption sessions.

The local k3s deployment is a separate verification surface. It currently runs explicitly named v0.4.1 development image pins (`server .18`, `job .16`, `web .19`, migration/export `.10`); creating the
source tag does not silently change or redeploy that stack.

## Performance evidence

The isolated release-candidate fixture covers ten years of daily history, 120 monthly media periods, and 12,000 expenses. The cache gate measured:

```json
{
  "cache_entry_count": 11,
  "cache_min_ttl_s": 86400,
  "cold_p50_ms": 1.28,
  "cold_p95_ms": 18.49,
  "hit_p50_ms": 0.36,
  "mutation_miss_ms": 1.46,
  "durable_read_model_decision": "defer"
}
```

The first rehearsal exposed a stale fixture that still inserted the retired `tb_media_progress.finished_at` column. The fixture now uses `completed_on_value` and `completed_on_precision`, so the test
data follows the canonical partial-date schema.

## Release contents

- Backend-neutral cache with Postgres, Valkey, and disabled modes; no process-memory cache or durable generic aggregate table.
- Server-owned overview/date projections and bounded frontend request shapes with post-commit cache invalidation.
- Canonical media provider state history and dated AniList activity updates, with exact event intake kept separate.
- Correct library filtering/current-status totals and media detail evidence without fabricated dates, totals, or internal observation snapshots.
- Shared theme assets remain package-owned and consumed by both private and public surfaces.

## Release handoff

The source tag is the local release boundary. No remote push, GitHub release publication, or production image rollout is claimed by this audit. Those actions require an explicit downstream handoff and
must use the owning repository's release/deployment procedure.
