# Iroha v0.4.1 release audit

Date: 2026-08-15 (updated same day, after live k3s testing surfaced and fixed two additional issues)

Source branch: `feat/iroha-0.4.1-cache`

Release boundary: local source tag `v0.4.1` (re-pointed at the hardened commit; the tag was never pushed, so moving it locally carries no remote history risk)

## Scope

This is the final release evidence for the v0.4.1 cache, canonical read-projection, media-history, and media-detail corrections, plus the follow-up hardening below that live testing on k3s surfaced
after the first local tag.

The canonical-data-first rule remains unchanged: Postgres is authoritative, the runtime cache is disposable, and provider snapshots are not exact consumption sessions.

### Post-tag hardening

Deploying the first `v0.4.1` cut to k3s and exercising it live (not just through the seeded release-candidate fixture) surfaced two problems the earlier gate run did not catch, because they only show
up on a genuine data refetch, not a cold load:

1. **Bounds-driven date navigation.** Arrow-key period shifts and month/year navigation could walk past the real imported data range. Fixed by clamping navigation to actual bounds instead of "today".
2. **Loading-state flicker on refetch.** `LoadingBoundary`'s `ready` flag was computed per-route as `!loading && ...`, which is non-sticky — it flips back to `false` on every refetch (a period switch,
   a filter change) and re-triggers the boundary's first-load treatment instead of the intended quiet "Updating…" pill. This was live on Motion, Night, Patterns, and Overview, and a shared chart
   component (`ActivityMetricChart.svelte`, used by all six themes) had its own unrelated unguarded DOM swap on the same refetch path. Root-caused and fixed at the source: a new shared
   `apps/iroha-web/src/lib/asyncResource.svelte.ts` primitive makes `ready` sticky by construction, and `LoadingBoundary` now takes the async resource(s) directly instead of a caller-computed
   `loading`/`ready` pair — the incorrect computation is no longer expressible. All nine `LoadingBoundary` call sites were migrated onto it. Verified live via `MutationObserver` during an actual
   Motion period switch: zero `inert`/`aria-hidden` toggles, no first-load overlay, table never replaced.

Also folded in during the same window: a distinct Book media family (ahead of any real book provider, deliberately — see `docs/roadmap.md`'s reading/watching module), a per-theme `--shell-width` token
consolidation, and a To-go page heading resize. None of these touch the cache/canonical-history contract this release is otherwise about.

## Performance evidence

The isolated release-candidate fixture covers ten years of daily history, 120 monthly media periods, and 12,000 expenses. The cache gate measured (this run, backend-only):

```json
{
  "cache_entry_count": 11,
  "cache_min_ttl_s": 86400,
  "cold_p50_ms": 1.25,
  "cold_p95_ms": 16.83,
  "hit_p50_ms": 0.38,
  "mutation_miss_ms": 0.86,
  "durable_read_model_decision": "defer"
}
```

Comparable to the first rehearsal's numbers (`cold_p95_ms` 18.49 → 16.83, `hit_p50_ms` 0.36 → 0.38) — no regression from the hardening changes, none of which touch the server or cache paths.

## Release contents

- Backend-neutral cache with Postgres, Valkey, and disabled modes; no process-memory cache or durable generic aggregate table.
- Server-owned overview/date projections and bounded frontend request shapes with post-commit cache invalidation.
- Canonical media provider state history and dated AniList activity updates, with exact event intake kept separate.
- Correct library filtering/current-status totals and media detail evidence without fabricated dates, totals, or internal observation snapshots.
- Shared theme assets remain package-owned and consumed by both private and public surfaces.
- Bounds-clamped period navigation; a shared `AsyncResource` primitive backing every route's loading state, ending the refetch-flicker class of bug structurally rather than per-route; a distinct Book
  media family; consolidated per-theme shell widths.

## Release handoff

The source tag is the local release boundary. No remote push, GitHub release publication, or production image rollout is claimed by this audit. Those actions require an explicit downstream handoff and
must use the owning repository's release/deployment procedure.
