## Scope

v0.5 is a fresh-schema cut-over rework. The new database is created from SQLx migrations 00001–00020 and populated by replaying the complete original raw evidence set. Legacy-schema migration is
explicitly out of scope, and Goose is not adopted.

The product goal is lower-interruption personal data operations: raw evidence is retained, imports are replayable, bounded defaults run automatically, source coverage is visible, and agent actions
replace a human resolution inbox.

## Cut-over handoff

1. Preserve the original raw export outside the database backup set.
2. Create the target Postgres/PostGIS database and apply SQLx migrations 00001–00020.
3. Upload the preserved raw evidence and enqueue imports; verify source receipts, coverage, and canonical counts before switching readers.
4. Keep the old database available for rollback until the acceptance checks and owner review are complete; rollback means switching back to the old service/database, not applying a legacy-schema
   migration.

The source candidate is ready for owner review and the physical Health trial. Remote publication, production images, and deployment remain separate explicitly authorized handoffs.
