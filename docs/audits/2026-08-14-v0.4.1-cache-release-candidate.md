# Iroha v0.4.1 cache release-candidate audit

Date: 2026-08-14

Branch: `feat/iroha-0.4.1-cache`

## Scope

This audit records the release evidence for the canonical-data-first cache and report-read work in [ADR 0004](../adr/0004-cache-correctness-and-report-reads.md). The cache is disposable; canonical
Postgres records remain authoritative.

The implementation uses one backend-neutral module in `apps/iroha-runtime/cache` with `postgres`, `valkey`, and `none` modes. There is no production process-memory cache. Direct expense records remain
uncached; derived expense metrics and report responses use the `read_metrics` and `read_reports` namespaces.

## Deterministic performance fixture

The candidate seeded:

- ten years of daily, activity, sleep, and media history;
- 120 monthly media periods;
- 12,000 expenses, or 100 per month;
- empty and partial report periods through the existing release fixture.

The performance gate measured the following against the isolated Postgres-backed production server:

```json
{
  "cache_entry_count": 8,
  "cache_min_ttl_s": 86400,
  "cold_p50_ms": 1.11,
  "cold_p95_ms": 19.62,
  "hit_p50_ms": 0.37,
  "mutation_miss_ms": 1.12,
  "durable_read_model_decision": "defer"
}
```

All day/month/year metric requests and the twelve-month report series followed `MISS -> HIT`; an expense mutation caused the dependent metric read to return `MISS`. PostgreSQL query-statistics
evidence was unavailable in the isolated image, so this gate records latency and cache behavior, not a `pg_stat_statements` claim.
